## 1. 전체 아키텍처 개요

```
┌──────────────────────────────────────────────────┐
│              FRONTEND (React TS)                 │
│  - Vite + React 18 + TypeScript                  │
│  - React Router v6 (SPA 라우팅)                  │
│  - Zustand (전역 상태관리)                        │
│  - React Query / TanStack Query (서버 상태)      │
│  - Axios (HTTP 클라이언트)                        │
│  - STOMP.js / SockJS (WebSocket - 그룹 뽑기)     │
└──────────────────────┬───────────────────────────┘
                       │ REST API (JSON)
                       │ HTTP/HTTPS
                       │ WebSocket (STOMP)
┌──────────────────────▼───────────────────────────┐
│              BACKEND (Spring Boot)               │
│  - Java 17 + Spring Boot 3.x                     │
│  - Spring Security + JWT                         │
│  - Spring Data JPA + QueryDSL                    │
│  - Spring WebSocket (STOMP)                      │
│  - 화면 렌더링 코드 없음 (@RestController 전용)  │
└──────────────────────┬───────────────────────────┘
                       │ JPA / JDBC
┌──────────────────────▼───────────────────────────┐
│              DATABASE (MySQL 8.x)                │
└──────────────────────────────────────────────────┘
```

### 레이어 기준 vs 도메인 기준 비교

| 구분 | 레이어 기준 (이전) | **도메인 기준 (채택)** |
|---|---|---|
| 폴더 구조 | `controller/`, `service/`, `repository/` | `gacha/`, `user/`, `curation/` |
| 팀 개발 | 여러 명이 같은 폴더 → **충돌 많음** | 담당 도메인 폴더만 작업 → **충돌 최소** |
| 파악 난이도 | 기능 하나를 보려면 폴더 3~4개 이동 | 한 폴더 안에 관련 코드 전부 존재 |
| 확장성 | 도메인 추가 시 폴더마다 파일 추가 | 도메인 폴더 하나 추가로 완결 |

## 2. 공통 컴포넌트 분석 (화면 기반)

### 2-1. 패턴 분석 결과

| 구분 | 공통 요소 | 등장 화면 |
|---|---|---|
| **레이아웃** | 하단 네비게이션 바 (홈/뽑기/마이트립/마이) | 홈, 큐레이션, 마이트립, 마이페이지 |
| **레이아웃** | 상단 로고 헤더 (로고 + 알림 벨) | 홈, 마이페이지 |
| **레이아웃** | 뒤로 가기 헤더 (← 타이틀 [우측 액션]) | 회원가입, 설정, 뽑기 결과, 큐레이션 상세 등 |
| **레이아웃** | 인증 화면 레이아웃 (풀스크린, 네비 없음) | 온보딩, 로그인, 회원가입 |
| **UI** | 기본 버튼 (Primary / Secondary / Ghost) | 전 화면 |
| **UI** | 태그/칩 (해시태그, 여행 스타일 선택) | 뽑기 결과, 큐레이션, 조건 설정 |
| **UI** | 카드 (여행 기록, 큐레이션 목록, 장소) | 큐레이션 홈, 마이트립 기록 |
| **UI** | D-Day 히어로 배너 카드 | 큐레이션 홈 |
| **UI** | 아바타 + 이름 행 (멤버 리스트) | 그룹 대기실 |
| **UI** | 통계 카드 (숫자 + 라벨) | 마이페이지, 마이트립 |
| **UI** | 탭 스위처 (세그먼트 컨트롤) | 마이트립 |
| **UI** | 필터 탭 바 (전체/예정/지난 여행) | 큐레이션 홈 |
| **UI** | 폼 인풋 (라벨 + 입력창) | 회원가입, 닉네임 변경, 조건 설정 |
| **UI** | 슬라이더 | 이동 거리, 예산 |
| **UI** | 카운터 인풋 (- 숫자 +) | 여행 인원 수 |
| **UI** | 바텀 시트 (모달 반시트) | 뽑기 모드 선택, 공유, 확정 확인 등 |
| **UI** | 스켈레톤 로딩 카드 | 데이터 로딩 중 전체 |
| **UI** | 빈 상태 (EmptyState) | 여행 기록 없음 등 |
| **UI** | 메뉴 리스트 행 (라벨 + 우측 화살표/값) | 마이페이지 설정 |

### 2-2. 컴포넌트 재사용 매핑

```
BottomNavigation      ← 홈, 큐레이션, 마이트립, 마이페이지
AppHeader             ← 홈, 마이페이지
BackHeader            ← 회원가입, 프로필 수정, 닉네임 변경, 뽑기 결과, 큐레이션 상세 외 14개
Button                ← 모든 CTA 버튼 (Primary/Secondary/Ghost/소셜)
Tag                   ← 뽑기 결과 해시태그, 스타일 선택 태그, 지역 선택
TravelCard            ← 큐레이션 홈 저장된 여행, 마이트립 기록 목록
HeroBannerCard        ← 큐레이션 홈 다가오는 여행
StatCard              ← 마이페이지 통계, 마이트립 지도 하단
MemberRow             ← 그룹 대기실
TabSwitcher           ← 마이트립 (여행지도 / 여행기록)
FilterTabBar          ← 큐레이션 홈 (전체/예정/지난여행)
FormInput             ← 회원가입, 닉네임 변경, 조건 설정 텍스트 입력
BottomSheet           ← 뽑기 모드 선택, 공유하기, 확정 확인
SliderInput           ← 이동 거리 조건, 관리자 가챠 정책 가중치
CounterInput          ← 여행 인원 수
MenuListItem          ← 마이페이지 설정 메뉴 전체
SkeletonCard          ← 큐레이션 목록, 마이트립 기록, 여행지 상세
EmptyState            ← 큐레이션 없음, 여행 기록 없음, 배지 없음
```

## 4. 백엔드 프로젝트 구조 — 도메인 기준

> 레이어(controller/service/repository) 기준이 아닌 **도메인(기능) 기준**으로 패키지를 나눕니다.  
> 각 도메인 폴더 안에 controller/service/repository/domain/dto가 함께 있습니다.

```
gachatrip-backend/
└── src/main/java/com/gachatrip/
    │
    ├── GachatripApplication.java
    │
    ├── global/                              # 전역 공통 (어느 도메인에도 속하지 않음)
    │   ├── config/
    │   │   ├── SecurityConfig.java          # Spring Security + JWT
    │   │   ├── WebMvcConfig.java            # CORS 설정
    │   │   ├── WebSocketConfig.java         # STOMP WebSocket
    │   │   ├── SwaggerConfig.java           # OpenAPI 문서화
    │   │   ├── JpaConfig.java               # JPA Auditing
    │   │   └── AsyncConfig.java             # 비동기 스레드풀
    │   │
    │   ├── exception/
```

### 6-1. 한국관광공사 TourAPI 4.0

**공식 문서**: https://api.visitkorea.or.kr  
**발급처**: 공공데이터포털 (data.go.kr) — 국문 관광정보 서비스 신청  
**Base URL**: `https://apis.data.go.kr/B551011/KorService1`  
**인증 방식**: Query Parameter `serviceKey={발급키}`

#### 사용 목적 및 담당 도메인

| 도메인 | 사용 목적 | 담당 개발자 |
|---|---|---|
| `destination/` | 전국 여행지 초기 데이터 수집 (DB 적재) | B |
| `curation/` | AI 큐레이션 생성 시 장소 상세 정보 조회 | C |

#### 주요 사용 엔드포인트

| API | 엔드포인트 | 용도 |
|---|---|---|
| 지역기반 관광정보 조회 | `GET /areaBasedList1` | 시/도 코드 기반 관광지 목록 수집 |
| 공통정보 조회 | `GET /detailCommon1` | 관광지 상세 (이름, 주소, 좌표, 이미지) |
| 위치기반 관광정보 조회 | `GET /locationBasedList1` | 특정 위·경도 반경 내 장소 검색 |
| 키워드 검색 | `GET /searchKeyword1` | 검색어 기반 관광지 추출 |
| 행사정보 조회 | `GET /searchFestival1` | 기간별 행사/축제 정보 |

#### 주요 파라미터 (areaBasedList1)

| 파라미터 | 설명 | 예시 |

## 7. 프론트-백 통신 원칙

### Axios 클라이언트 (api/client.ts)

```typescript
const instance = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  timeout: 10000,
});

// JWT 자동 첨부
instance.interceptors.request.use((config) => {
  const token = storage.getAccessToken();
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

// 401 → 자동 토큰 갱신
instance.interceptors.response.use(
  (res) => res,
  async (error) => {
    if (error.response?.status === 401) {
      const newToken = await refreshAccessToken();
      error.config.headers.Authorization = `Bearer ${newToken}`;
      return instance(error.config);
    }
    return Promise.reject(error);
  }
);
```
